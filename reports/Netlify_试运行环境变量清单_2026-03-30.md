# Netlify 试运行环境变量清单

日期：2026-03-30  
适用范围：风控系统第一版 Netlify 试运行环境

## 一、环境变量总表

| 变量名 | 用途 | 是否必填 | Build 用 / Functions Runtime 用 | 试运行是否必须配置 |
|---|---|---|---|---|
| `DATABASE_URL` | PostgreSQL 连接串，供 Prisma 和所有真实业务接口读取数据 | 是 | Build + Functions Runtime | 是 |
| `SITE_ACCESS_PASSWORD` | 站点登录访问密码，用于试运行期间控制访问 | 强烈建议填写 | Functions Runtime | 是（建议） |
| `NODE_ENV` | 运行模式标识，Netlify 会自动处理 | 否 | Build + Runtime | 否 |

## 二、各变量说明

### 1. `DATABASE_URL`

#### 用途
- 提供 PostgreSQL 数据库连接
- 当前这些页面和接口都依赖它：
  - `/customers`
  - `/customers/[id]`
  - `/risk`
  - `/risk/customers`
  - `/risk/projects`
  - 以及对应 API

#### 是否必填
- **必填**

#### 用于哪个阶段
- **Build**
  - Prisma 生成与部分构建链路需要稳定识别数据库配置
- **Functions Runtime**
  - 运行期读取客户、项目、风险数据时必须使用

#### 试运行是否必须配置
- **必须配置**

#### 配置建议
- 建议使用试运行专用 PostgreSQL 连接串
- 如果数据库提供连接池连接串，试运行阶段优先用池化连接串

---

### 2. `SITE_ACCESS_PASSWORD`

#### 用途
- 控制试运行站点登录访问密码
- 当前系统代码中虽然有默认值，但试运行建议不要依赖默认密码

#### 是否必填
- 从代码层说不是硬性必填
- 从试运行管理角度说：**建议视为必填**

#### 用于哪个阶段
- **Functions Runtime**
  - 登录页和登录逻辑使用

#### 试运行是否必须配置
- **建议必须配置**

#### 配置建议
- 试运行专用密码不要和本地演示密码完全混用
- 如果同时启用了 Netlify 站点密码保护，这个密码属于系统内登录层，不冲突

---

### 3. `NODE_ENV`

#### 用途
- 标准运行模式环境变量
- 当前项目会用它控制 Prisma 日志等级等细节

#### 是否必填
- 否

#### 用于哪个阶段
- Build + Runtime

#### 试运行是否必须配置
- 否

#### 配置建议
- 通常由平台自动处理，无需手工填写

## 三、当前试运行不建议先纳入的变量范围

当前项目里没有发现“第一版试运行必须额外配置”的第三方正式服务变量。  
例如：
- 天眼查同步接口当前还是 mock 占位
- 不构成试运行前置条件

因此，第一版试运行的核心环境变量，实际只需要先确保：
1. `DATABASE_URL`
2. `SITE_ACCESS_PASSWORD`

## 四、Build 与 Runtime 的区别说明

### Build 用
这类变量在 Netlify 构建阶段就可能被读取：
- `DATABASE_URL`

### Functions Runtime 用
这类变量在站点运行后由 API / 服务端逻辑读取：
- `DATABASE_URL`
- `SITE_ACCESS_PASSWORD`

## 五、试运行建议配置结论

### 最小必配
- `DATABASE_URL`
- `SITE_ACCESS_PASSWORD`

### 推荐策略
- `DATABASE_URL`：连接试运行数据库
- `SITE_ACCESS_PASSWORD`：设置试运行专用密码

## 六、一句话结论

当前 Netlify 试运行环境变量的最小可用集合就是：
- `DATABASE_URL`
- `SITE_ACCESS_PASSWORD`

只要这两个变量配置正确，并且数据库对 Netlify 可达，第一版页面和风控能力就具备试运行条件。
