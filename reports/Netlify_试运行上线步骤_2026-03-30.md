# Netlify 试运行上线步骤

日期：2026-03-30  
定位：试运行环境上线步骤，不作为正式生产上线步骤

## 一、上线原则

本次试运行目标是：
- 让领导、业务、财务可以访问第一版系统
- 验证客户总账页、完整账款档案页、风控模块第一版是否可用

本次**不以正式生产为目标**，因此建议：
- 启用 Netlify 站点访问保护
- 使用试运行专用数据库
- 先验证“看数据、查风险、查档案”
- 暂不把“在线 Excel 导入”纳入试运行能力范围

## 二、执行顺序总览

1. 代码准备  
2. Netlify 站点创建  
3. 环境变量配置  
4. 首次构建部署  
5. 试运行访问控制  
6. 功能验收  
7. 问题记录与回归

## 三、具体执行步骤

### 第一步：代码准备

#### 你做什么
- 确认当前代码使用的是准备上线的第一版分支/版本
- 确认试运行时不把“在线 Excel 导入”作为必须能力

#### 我做什么
- 协助确认当前版本是否已经达到试运行范围
- 协助检查是否还有阻塞上线的问题

#### 每一步验收看什么
- 当前版本是否已经包含：
  - `/login`
  - `/customers`
  - `/risk`
  - `/risk/customers`
  - `/risk/projects`
- 交付材料是否已整理齐全

---

### 第二步：Netlify 创建站点

#### 你做什么
- 在 Netlify 中从当前代码仓库创建一个新站点
- 站点建议命名为试运行用途，例如：
  - `zc-risk-trial`
  - `credit-risk-trial`

#### 我做什么
- 协助确认构建命令和部署设置是否合理

#### 每一步验收看什么
- Netlify 站点创建成功
- 已连上正确仓库和分支

---

### 第三步：配置环境变量

#### 你做什么
在 Netlify Site settings -> Environment variables 中配置：
- `DATABASE_URL`
- `SITE_ACCESS_PASSWORD`

#### 我做什么
- 协助核对变量名是否拼写正确
- 协助判断是否还缺变量

#### 每一步验收看什么
- 变量已保存
- 无拼写错误
- 使用的是试运行环境值，不是本地临时值

---

### 第四步：配置构建与部署

#### 你做什么
在 Netlify 中确认：
- Build command
- Next.js 站点识别正常

建议第一版先用：
- Build command：`npm run build`

如果构建中 Prisma Client 有问题，再按我建议补：
- `npm run prisma:generate && npm run build`
或在项目中补 `postinstall`

#### 我做什么
- 协助看首轮构建日志
- 如果构建失败，协助定位是：
  - Prisma
  - 数据库连接
  - Next.js 适配
  - 运行时不兼容

#### 每一步验收看什么
- Build 是否成功
- 没有 Prisma Client 缺失问题
- 没有 Next.js 构建中断问题

---

### 第五步：启用试运行访问保护

#### 你做什么
- 在 Netlify 启用站点密码保护或访问限制
- 同时保留系统内登录页密码

#### 我做什么
- 协助确认双层保护是否符合试运行目标

#### 每一步验收看什么
- 未授权用户无法直接打开试运行站点
- 授权用户能进入登录页

---

### 第六步：试运行基础验证

#### 你做什么
- 打开 Netlify 试运行 URL
- 验证关键页面能访问

#### 我做什么
- 基于试运行 URL 配合你做一轮最小回归

#### 每一步验收看什么
至少验证：
- `/login`
- `/customers`
- `/risk`
- `/risk/customers`
- `/risk/projects`

并继续验证：
- 风控总览页 -> 风险客户页
- 风控总览页 -> 风险项目页
- 风险项目页 -> 客户详情页并带 `projectId`

---

### 第七步：记录问题并决定是否继续开放试运行

#### 你做什么
- 用《试运行问题清单》记录试运行问题
- 决定是否继续开放给更大范围人员体验

#### 我做什么
- 根据问题清单协助快速判断：
  - 阻塞问题
  - 非阻塞问题
  - 后续优化项

#### 每一步验收看什么
- 是否存在阻塞级问题
- 是否满足试运行范围内的最小可用标准

## 四、我建议的执行分工

### 你负责
- Netlify 后台创建站点
- 配置环境变量
- 启用密码保护
- 提供试运行 URL

### 我负责
- 检查构建和运行日志
- 解释部署问题根因
- 基于试运行 URL 做最小回归
- 输出问题归类建议

## 五、试运行上线后的最小验收口径

当以下条件都满足时，可以认为试运行环境上线成功：
- 登录页可访问
- 客户页可访问
- 风控总览页可访问
- 风险客户页可访问
- 风险项目页可访问
- 页面能看到真实数据库数据
- 关键跳转链路可用

## 六、当前已知边界

第一版试运行建议暂不纳入：
- 在线 Excel 导入
- 大批量脚本任务
- 自动化风险流转
- 预警记录页 / 规则配置页

这些不属于本次试运行上线的阻塞项。

## 七、一句话结论

本次 Netlify 试运行上线，建议按“先连通数据库、再构建部署、再做最小回归”的顺序推进。  
只要环境变量正确、数据库可达、构建通过，当前第一版页面和风控模块就具备试运行上线条件。
