# 本周整改执行计划

日期：2026-03-27

## 目标

本周不展开新功能，聚焦已验收系统的整改收口，优先保证：

- 数据可信
- 页面可验收
- 本地运行稳定

## 执行范围

仅处理以下 5 项，按顺序推进：

1. 项目金额与原始客户 sheet 一致性收口
2. 未闭环项目分层处理
3. 项目层字段稳定性补强
4. 本地稳定启动链路收口
5. 原始档案重点样本复验

---

## 1. 项目金额与原始客户 sheet 一致性收口

- 优先级：P0
- 影响模块：项目金额聚合、客户总账页、客户详情页、原始档案联动
- 修复目标：
  - 确保项目层 `receivableAmount / contractReceivable / receivedAmount / unpaidAmount` 统一以原始客户 sheet 为准
  - 避免总表、汇总、原始 sheet 重复叠加
  - 保持页面、接口、原始 sheet 三方一致
- 验收标准：
  - 云龙小学闭环保持正确
  - 可对比项目再次全量复核后，不一致项目数维持在 0
  - `/api/customers/ledger`、`/customers` 页面项目值、原始 sheet 汇总值一致
  - 重点样本至少 10 个复核通过

## 2. 未闭环项目分层处理

- 优先级：P1
- 影响模块：项目金额验收、原始档案补录、后续风控数据可信度
- 修复目标：
  - 将未闭环项目按原因拆分：
    - 原始 sheet 缺失
    - 原始 sheet 字段不完整
    - 项目归并待确认
    - merged 副本干扰
    - 其他
  - 明确哪些项目继续补档，哪些项目允许暂时使用总表
- 验收标准：
  - 形成完整问题清单
  - 每个未闭环项目都有明确原因和处理建议
  - 高金额 / 高风险项目被单独标出

## 3. 项目层字段稳定性补强

- 优先级：P1
- 影响模块：客户总账页、项目展开层、导入字段质量、后续风控判断
- 修复目标：
  - 补强项目层 `项目归属 / 资信状况 / 目前状况` 的结构化稳定性
  - 保持展示逻辑为：
    - 结构化字段优先
    - 摘要回退
    - 空态兜底
  - 降低页面对 fallback 的依赖
- 验收标准：
  - 总表 / 汇总 / 已结清单位 / 项目复杂客户样本复核通过
  - 输出三项字段完成度结果
  - `/api/customers/ledger` 项目层字段稳定返回

## 4. 本地稳定启动链路收口

- 优先级：P1
- 影响模块：本地启动、验收环境、开发环境、Prisma/PostgreSQL 连接稳定性
- 修复目标：
  - 固化本地只保留一套稳定入口
  - 避免多个 Next 进程并存
  - 避免 Prisma / PostgreSQL 连接被打满
  - 解决 `.next/export` 清理异常造成的稳定启动失败
- 验收标准：
  - `npm run local:stable` 可连续稳定启动
  - 固定端口可访问：
    - `/login` 返回 200
    - `/customers` 返回 200
  - 不再频繁出现旧端口缓存漂移问题

## 5. 原始档案重点样本复验

- 优先级：P1
- 影响模块：客户完整账款档案页、原始布局预览、原始 sheet 映射可信度
- 修复目标：
  - 对重点样本再次复验：
    - 左主表
    - 右辅助区
    - 底部汇总区
    - 默认定位对应 sheet
    - 日期字段格式
  - 确保关键客户档案页可直接验收
- 验收标准：
  - 至少复验 3 类样本：
    - 云龙小学类
    - 底部汇总复杂类
    - 多 sheet 类
  - 确认“原始布局预览”与数据库二维结构一致
  - `结算期间 / 应回款月份` 不再显示 Excel 序列号

## 执行原则

- 先修数据可信度，再修展示稳定性
- 先保证验收链路可复核，再进入下一阶段
- 不展开风控新功能，先把底座收稳
