# 风控模块第一版风控规则清单

日期：2026-03-29

适用范围：
- 风控总览页
- 风险客户列表页
- 风险项目列表页
- 第一版后端风控规则层与聚合接口

---

## 一、规则来源原则

第一版风控规则的来源原则是：

1. **优先基于《应收账款情况汇总表》的既有逻辑**
- 不凭空重造一套完全脱离业务现状的新规则
- 先从原有汇总表中提炼公司已经在使用的判断口径

2. **先还原旧规则，再结构化，再做少量系统化增强**
- 先还原：
  - 金额风险
  - 回款节点风险
  - 诉讼/资信风险
  - 结算异常风险
- 再把这些规则结构化成系统可执行规则
- 最后只补少量第一版必须的系统增强规则，例如：
  - 高金额且高未收叠加
  - 新增预警统计

3. **第一版目标不是做复杂评分模型**
- 第一版重点是：
  - 算风险
  - 看风险
  - 查风险
- 先保证规则可解释、页面可读、业务可接受

---

## 二、规则分层

第一版风控规则按 4 层组织：

### 1. 客户级风险规则
主要用于识别：
- 客户整体是否存在明显风险
- 客户级文本信息里是否已表达风险判断
- 客户名下项目风险是否已经上卷成整体风险

典型来源字段：
- `remark`
- `riskRemark`
- `currentStatus`
- 客户名下项目规则命中结果
- 系统已有风险记录

### 2. 项目级风险规则
主要用于识别：
- 项目金额和未收风险
- 项目业务类型风险
- 项目回款比例异常
- 项目结算异常
- 项目诉讼状态

典型来源字段：
- `receivableAmount`
- `contractReceivable`
- `receivedAmount`
- `unpaidAmount`
- `businessType`
- `remarkSummary`
- `creditStatusSummary`
- `currentStatusSummary`

### 3. 应收节点类风险规则
主要用于识别：
- 应回款月份已到但回款未按计划落实
- 回款节奏异常
- 节点明显落后

典型来源字段：
- 原始 sheet 右侧辅助区：
  - `应回款月份`
  - `回款金额`
  - `实际收款时间`

### 4. 系统已有风险记录触发规则
主要用于识别：
- 系统里已经存在的高等级风险记录
- 诉讼类风险是否已沉淀
- 风险总览里的新增预警统计

典型来源字段：
- `risk_records`
  - `riskType`
  - `riskLevel`
  - `status`
  - `detectedAt`

## 三、第一版已落地规则清单

> 说明：
> 第一版页面和接口当前主要依赖以下规则。

### R-001 大额未收风险

- 规则编号：`R-001`
- 规则名称：大额未收风险
- 适用层级：项目级 / 客户级（项目上卷）
- 触发条件：
  - `unpaidAmount > 阈值`
  - 第一版主要配合 `R-011` 使用，不单独做太复杂分层
- 风险等级影响：
  - 中风险起步
  - 与其他规则叠加后可上升
- 风险原因展示文案：
  - `未收金额较大`
- 建议动作：
  - `持续跟进回款`
- 当前实现状态：
  - **部分落地**
- 说明：
  - 第一版更常通过 `R-011` 来体现“大额未收 + 高金额叠加”效果

---

### R-002 回款比例过低

- 规则编号：`R-002`
- 规则名称：回款比例过低
- 适用层级：项目级 / 客户级（项目上卷）
- 触发条件：
  - `receivedAmount / contractReceivable`
  - 边界：
    - `contractReceivable <= 0` 时不触发
  - 第一版阈值：
    - `>= 0.8`：不触发
    - `< 0.8 且 >= 0.5`：中风险
    - `< 0.5 且 >= 0.2`：高风险
    - `< 0.2`：极高风险
- 风险等级影响：
  - 中风险 / 高风险 / 极高风险
- 风险原因展示文案：
  - `项目回款比例偏低`
  - 明细示例：
    - `已收金额占按合同应收金额比例仅为 xx%`
- 建议动作：
  - 中风险：`持续跟进回款`
  - 高风险：`加快催收并核对应收节点`
  - 极高风险：`立即升级跟进并评估法律/保全措施`
- 当前实现状态：
  - **已完整落地**

---

### R-003 待起诉 / 已诉项目

- 规则编号：`R-003`
- 规则名称：待起诉 / 已诉项目
- 适用层级：项目级 / 客户级（项目上卷）
- 触发条件：
  - `businessType in ('待起诉', '已诉', '诉')`
- 风险等级影响：
  - 高风险
- 风险原因展示文案：
  - `存在诉讼或待起诉项目`
- 建议动作：
  - `跟进诉讼进展`
  - `加快催收`
- 当前实现状态：
  - **已完整落地**

- 当前实现状态：
  - **已完整落地**

### R-005 资金紧张 / 无法支付

- 规则编号：`R-005`
- 规则名称：资金紧张 / 无法支付
- 适用层级：客户级 / 项目级
- 触发条件：

    - `资金紧张`

  - 或 `客户备注中存在潜在风险提示`
- 建议动作：
  - `持续跟进回款`
  - `补充客户动态`
- 当前实现状态：
  - **已完整落地**

### R-006 跳票 / 追索风险

- 规则编号：`R-006`
- 规则名称：跳票 / 追索风险
- 适用层级：客户级 / 项目级
- 触发条件：

- 建议动作：

  - **部分落地**

### R-007 未办理结算 / 结算异常

- 规则编号：`R-007`
- 规则名称：未办理结算 / 结算异常
- 适用层级：项目级 / 客户级（项目上卷）
- 触发条件：
  - 文本命中：
    - `未办理结算`
    - `结算无签字`
    - `无盖章`
    - `未签订合同`
    - `合同主体不同`
- 风险等级影响：
  - 中风险 / 高风险
- 风险原因展示文案：
  - `项目结算基础不完整，存在债权确认风险`
- 建议动作：
  - `优先补齐结算资料并核对债权基础`
- 当前实现状态：
  - **部分落地**
- 说明：
  - 第一版已经能在文本风险原因中体现
  - 但尚未做到更精细的结构化结算标签体系

---

### R-009 应回款月份已到未回款

- 规则编号：`R-009`
- 规则名称：应回款月份已到未回款
- 适用层级：应收节点级 / 项目级 / 客户级（项目上卷）
- 触发条件：
  - 基于原始 sheet 右侧辅助区：
    - `应回款月份`
    - `回款金额`
    - `实际收款时间`
  - 第一版当前判断逻辑：
    1. 存在应回款月份
    2. 至少一个应回款月份 `<= 当前月份`
    3. 项目仍有 `unpaidAmount > 0`
    4. 且满足任一：
       - 无实际收款证据
       - 实际收款节点数落后于已到期应回款节点数
       - 到期进度明显快于实际回款进度
  - 升级为高风险的条件：
    - 已到期节点 `>= 2`
    - 且未收金额仍较大或节点差距明显
- 风险等级影响：
  - 中风险 / 高风险
- 风险原因展示文案：
  - `应回款月份已到但回款未按计划落实`
- 建议动作：
  - 中风险：`核对回款节点并持续催收`
  - 高风险：`重点核对应回款节点并升级催收处理`
- 当前实现状态：
  - **第一版简化实现**
- 说明：
  - 当前已从最初的简化版补强为“节点证据版”
  - 但还不是完整逐笔精算模型

---

### R-010 已有高等级风险记录

- 规则编号：`R-010`

- 风险等级影响：
  - 高风险
- 风险原因展示文案：
  - `系统中存在高等级风险记录`
- 建议动作：
  - `加快催收`
  - `优先核实现有风险事项`
- 当前实现状态：
  - **已完整落地**

---

### R-011 高金额且高未收叠加

- 规则编号：`R-011`
- 规则名称：高金额且高未收叠加
- 适用层级：项目级 / 客户级（项目上卷）
- 触发条件：
  - 基于：
    - `receivableAmount`
    - `unpaidAmount`
  - 第一版阈值：
    - 基础触发：
      - 应收金额 `>= 1000万`
      - 未收金额 `>= 100万`
    - 升级：
      - 应收金额 `>= 5000万` 且未收金额 `>= 500万`
    - 极高风险：
      - 应收金额 `>= 1亿` 且未收金额 `>= 1000万`
      - 或金额很大且未收占比明显偏高
- 风险等级影响：
  - 高风险 / 极高风险
- 风险原因展示文案：
  - `项目金额和未收金额同时较大`
- 建议动作：
  - 高风险：`优先催收并纳入重点项目跟进`
  - 极高风险：`立即升级管理层关注并评估风险处置方案`
- 当前实现状态：
  - **已完整落地**

---

### R-012 重点客户未闭环

- 规则编号：`R-012`
- 规则名称：重点客户未闭环
- 适用层级：客户级 / 项目级
- 触发条件：
  - `isImportantCustomer = true`
  - 且项目或客户档案未闭环
- 风险等级影响：
  - 中风险 / 高风险
- 风险原因展示文案：
  - `重点客户项目未闭环，影响风险判断可靠性`
- 建议动作：
  - `优先补齐原始档案并核对项目风险`
- 当前实现状态：
  - **部分落地**
- 说明：
  - 第一版主要通过：
    - `是否重点客户`
    - `是否未闭环`
    两个维度在页面展示
  - 还没有单独形成强规则抬升口径

## 四、第一版规则边界

### 1. 已经完整可用的规则
以下规则当前可视为第一版完整落地：
- R-002 回款比例过低
- R-003 待起诉 / 已诉项目
- R-004 诉讼关键词命中
- R-005 资金紧张 / 无法支付
- R-010 已有高等级风险记录
- R-011 高金额且高未收叠加

这些规则的特点是：
- 触发条件明确
- 风险等级影响明确
- 风险原因文案明确
- 建议动作明确
- 已稳定输出到后端聚合接口与页面

### 2. 第一版简化实现的规则
以下规则当前已能用，但仍保留第一版简化口径：
- R-009 应回款月份已到未回款

当前已做到：
- 节点证据版判断
- 结合：
  - 应回款月份
  - 回款金额
  - 实际收款时间
  - 当前未收情况

当前还没做到：
- 完整逐笔精算
- 每个节点回款金额与左表逐期严格核对

### 3. 部分落地的规则
以下规则第一版已能体现，但还未完全结构化：
- R-001 大额未收风险
- R-006 跳票 / 追索风险
- R-007 未办理结算 / 结算异常
- R-012 重点客户未闭环

这些规则的特点是：
- 已有业务意义
- 页面和接口已能反映
- 但结构化深度还不如核心规则完整

### 4. 暂未纳入第一版的规则
以下能力当前明确不纳入第一版：
- 预警流转规则
- 规则在线配置规则
- 外部工商/涉诉联动规则
- 精细信用评分模型
- 复杂批量处置规则

## 五、风险结果输出结构

第一版系统当前统一输出的核心风险结果结构包括：

### 1. `riskLevel`
表示最终风险等级。

当前页面使用的等级层级：
- `低风险`
- `中风险`
- `高风险`
- `极高风险`

### 2. `riskReasons`
表示风险原因列表。

用途：
- 页面直接展示
- 客户级、项目级都使用
- 已做第一版展示优化：
  - 去掉无意义占位文本
  - 优先展示明确风险原因

### 3. `riskActions`
表示建议动作列表。

用途：
- 页面直接展示
- 辅助业务和财务判断下一步应如何跟进

### 4. `triggeredRules`
表示命中的规则编号列表。

用途：
- 用于页面说明“为什么命中”
- 也便于后续接规则页、预警记录页、规则调试

### 5. 项目级规则明细（补充）
在项目级规则结果中，当前还会进一步输出每条规则的结构化明细：
- `ruleCode`
- `matched`
- `riskLevel`
- `reason`
- `detail`
- `action`

这使得第一版已经具备：
- 页面展示
- 后端复用
- 后续继续接预警页 / 规则页
的基础能力

## 六、当前总体结论

风控模块第一版当前的规则体系，可以概括为：

- 规则来源清楚
  - 以《应收账款情况汇总表》的既有逻辑为基础
- 规则结构清楚
  - 客户级
  - 项目级
  - 应收节点级
  - 系统已有风险记录级
- 规则输出清楚
  - `riskLevel`
  - `riskReasons`
  - `riskActions`
  - `triggeredRules`
- 规则边界清楚
  - 哪些完整落地
  - 哪些简化实现
  - 哪些暂未纳入第一版

这意味着：
- 第一版风控模块已经不是“页面展示”层面的原型
- 而是已经形成了可解释、可交付、可继续扩展的一套规则底座
