# 风控模块第一版整改完成情况

日期：2026-03-30

适用范围：
- 第一版客户总账主链路
- 第一版完整账款档案页
- 第一版风控模块
- 第一版本地运行与验收环境

## 一、整改背景

第一版开发和验收过程中，系统主干功能已经搭起来，但在进入正式验收后，暴露出一批会直接影响“能不能放心交付”的问题。  
这些问题大致分为 5 类：

1. **数据正确性问题**
- 项目金额口径与原始客户 sheet 不一致
- 某些项目直接用了总表 receivables 作为项目真值
- 会导致页面金额与原 Excel 明显对不上

2. **数据清洁性问题**
- `合计 / 单位 / 购货单位 / 待补数据` 这类统计行、占位值进入了真实数据链路
- 会污染客户页、风控页和 Top 列表的阅读结果

3. **页面与阅读体验问题**
- 页面能用，但一些展示文案会影响判断效率
- 典型问题包括：
  - `待补数据`
  - `当前未发现明显异常` 与明确风险原因并列

4. **风控规则精度问题**
- 第一版核心规则已具备雏形，但部分规则只停留在简化版
- 例如：
  - `R-009 应回款月份已到未回款`
  初版只看“到期月份 + 未收金额”，节点判断精度不够

5. **运行与验收环境问题**
- 本地/验收环境存在：
  - 旧进程并存
  - `.next` 残留
  - 稳定入口漂移
- 会导致“页面是否真的可用”无法稳定复验

因此，在第一版功能基本完成后，必须再做一轮**系统性整改**，目的不是扩功能，而是：
- 把口径收稳
- 把数据收干净
- 把页面阅读体验收顺
- 把风控规则收成可解释、可交付的版本

### B. 数据清洁性整改

### C. 页面与阅读体验整改

## 三、每项整改内容

### A. 数据正确性整改

#### 1. 项目金额与原始客户 sheet 一致性收口

- 整改项名称：
  - 项目金额口径收口
- 问题表现：
  - 网站项目金额与原始客户 sheet 明显不一致
  - 典型样本：
    - 成都永安建设集团有限公司 / 云龙小学
- 根因：
  - 旧逻辑直接使用总表 receivables 聚合作为项目金额
  - 没有优先以原始客户 sheet 作为项目真值
- 已采取措施：
  - 将项目金额口径调整为：
    - 原始客户 sheet 优先
    - receivables 仅 fallback
  - merged 副本做去重处理
- 当前结果：
  - 云龙小学等典型样本已完成闭环
  - 可比项目全量对账后，项目金额主问题已收敛
- 是否闭环：
  - 是
- 是否仍有后续增强空间：
  - 有，主要在未闭环项目补档，而不是金额规则本身

#### 2. 未闭环项目分层处理

- 整改项名称：
  - 未闭环项目原因分层
- 问题表现：
  - 仍有一批项目无法完全按原始客户 sheet 做闭环校验
- 根因：
  - 原始 sheet 缺失
  - 原始 sheet 字段不完整
- 已采取措施：
  - 已形成未闭环项目清单
  - 已按原因分层
  - 已识别高优先级治理对象
- 当前结果：
  - 未闭环项目已不再混在“系统错误”里，而是变成可治理清单
- 是否闭环：
  - 部分闭环
- 是否仍有后续增强空间：
  - 有，需要继续补原始档案或人工核对

#### 3. 项目层字段稳定性补强

- 整改项名称：
  - 项目归属 / 资信状况 / 目前状况 稳定性补强
- 问题表现：
  - 项目层这 3 个字段在展示上可用，但结构化落库不够稳定
- 根因：
  - 源 Excel 项目行字段不均匀
  - 导入与项目补写链路早期不够稳
- 已采取措施：
  - 补了项目上下文字段回填逻辑
  - 强化项目层补写规则
- 当前结果：
  - `项目归属` 基本稳定
  - `资信状况 / 目前状况` 已改善，但仍保留摘要回退
- 是否闭环：
  - 基本闭环
- 是否仍有后续增强空间：
  - 有，可继续提高项目层结构化覆盖率

---

### B. 数据清洁性整改

#### 4. 假客户 / 假项目噪声过滤

- 整改项名称：
  - 噪声主体识别与过滤
- 问题表现：
  - `合计` 这类统计行出现在客户接口和风控页面中
- 根因：
  - 历史导入时，统计行 / 表头行被误识别成真实客户或项目
- 已采取措施：
  - 接口层统一过滤：
    - `/api/customers`
    - `/api/customers/ledger`
    - `/api/risk/customers`
    - `/api/risk/projects`
  - 导入逻辑新增排除规则，阻止后续再次导入
  - 输出存量脏数据清理清单
- 当前结果：
  - `合计 / 单位 / 购货单位 / 工程项目 / 待补数据` 等假主体不再进入前台主页面展示
- 是否闭环：
  - 是（逻辑层闭环）
- 是否仍有后续增强空间：
  - 有，可视需要再做数据库物理清理

#### 5. 风控页面占位文本清理

- 整改项名称：
  - `待补数据` 占位文案清理
- 问题表现：
  - 风控页面中存在明显无业务意义的摘要占位文本
- 根因：
  - 摘要字段直接透出了占位值
- 已采取措施：
  - 在页面展示层统一清理 / 弱化：
    - 纯 `待补数据`
    - `待补数据` 夹杂分隔符的组合
  - 无有效信息时替换为空态文案
- 当前结果：
  - 风控总览页、风险客户页、风险项目页主展示区域已不再出现 `待补数据`
- 是否闭环：
  - 是
- 是否仍有后续增强空间：
  - 有，后续可继续决定是否同步清理接口原始摘要值

### C. 页面与阅读体验整改

#### 6. 风险客户原因展示优化

- 整改项名称：
  - 客户级风险原因聚合与排序优化
- 问题表现：
  - `当前未发现明显异常` 会与明确风险原因并列
  - 客户级风险原因是简单拼接，顺序不利于判断
- 根因：
  - 客户级原因由：
    - 客户自身风险原因
    - 项目上卷风险原因
    简单去重拼接得到
- 已采取措施：
  - 客户级风险原因改成有优先级的聚合
  - 当存在明确风险原因时，不再保留默认文案
  - 原因按业务优先级和命中频次排序
- 当前结果：
  - 风险客户列表页从“待调整”提升为“通过（MVP通过）”
- 是否闭环：
  - 是
- 是否仍有后续增强空间：
  - 有，可继续优化建议动作分层

#### 7. 风控总览页 Top 客户排序优化

- 整改项名称：
  - Top 客户综合优先级排序
- 问题表现：
  - 旧排序偏“风险等级优先”，不够贴近管理层先看谁的直觉
- 根因：
  - 过度依赖风险等级，未充分考虑未收金额和高风险项目数
- 已采取措施：
  - 改成综合优先级排序，综合考虑：
    - 风险等级
    - 总未收金额
    - 高风险项目数量
    - 是否重点客户（轻量加权）
- 当前结果：
  - Top 客户顺序更贴近“风险敞口优先”
- 是否闭环：
  - 是
- 是否仍有后续增强空间：
  - 有，可继续微调权重

#### 8. 风险项目页项目归属筛选结构化

- 整改项名称：
  - 项目归属固定选项筛选
- 问题表现：
  - 原项目归属筛选只是文本包含匹配，不够稳定
- 根因：
  - `projectBelonging` 真实分布中既有主体类型，也有项目自由文本
- 已采取措施：
  - 将筛选升级为固定选项：
    - 央企
    - 国企
    - 民营
    - 项目类
    - 未标注
  - 行内仍保留原始业务文本
- 当前结果：
  - 风险项目页筛选更稳、更易用
- 是否闭环：
  - 是
- 是否仍有后续增强空间：
  - 有，可后续继续扩展归属分类字典

### D. 风控规则整改

#### 9. R-002 回款比例过低

- 整改项名称：
  - 回款比例规则正式落地
- 问题表现：
  - 早期风控展示能看到风险，但缺少稳定统一的回款比例规则
- 根因：
  - 规则口径未完全沉到统一后端规则层
- 已采取措施：
  - 统一实现：
    - `receivedAmount / contractReceivable`
  - 明确第一版阈值和动作输出
- 当前结果：
  - R-002 已完整落地，并已接入风控页面
- 是否闭环：
  - 是
- 是否仍有后续增强空间：
  - 不属于当前关键缺口

#### 10. R-011 高金额且高未收叠加

- 整改项名称：
  - 高金额高未收叠加规则落地
- 问题表现：
  - 早期只能看金额，缺少管理层最关心的“大额敞口”上浮逻辑
- 根因：
  - 未形成明确阈值和规则输出
- 已采取措施：
  - 按第一版阈值实现：
    - 大额
    - 高未收
    - 极高风险升级
- 当前结果：
  - R-011 已完整落地，并在总览页、客户页、项目页统一生效
- 是否闭环：
  - 是
- 是否仍有后续增强空间：
  - 后续可继续调阈值，但不阻塞第一版

#### 11. R-009 应回款月份已到未回款

- 整改项名称：
  - 节点风险规则精度补强
- 问题表现：
  - 初版 R-009 只按“到期月份 + 未收金额”判断，精度不够
- 根因：
  - 右侧辅助区数据已存在，但未充分利用：
    - 应回款月份
    - 回款金额
    - 实际收款时间
- 已采取措施：
  - 将 R-009 从简化版补强为“节点证据版”
  - 同时参考：
    - 应回款月份
    - 回款金额
    - 实际收款时间
    - 当前未收情况
- 当前结果：
  - R-009 已比第一版初态更可信，风控项目页已能更合理地体现节点异常
- 是否闭环：
  - 基本闭环
- 是否仍有后续增强空间：
  - 有，后续可继续向逐笔精算模型推进

#### 12. `newAlertCount` 稳定口径落地

- 整改项名称：
  - 新增预警数统计口径落地
- 问题表现：
  - 风控总览页中的 `newAlertCount` 早期为 `null / 占位`
- 根因：
  - 不是没有数据，而是没有正式统计口径
- 已采取措施：
  - 明确第一版口径：
    - 最近 7 天新增且当前仍为 open 的风险记录数
- 当前结果：
  - 总览页 `newAlertCount` 已有稳定值和稳定解释
- 是否闭环：
  - 是
- 是否仍有后续增强空间：
  - 有，后续可做“新增高风险客户 / 新增高风险项目”等更细分统计

  - 固定稳定启动方式
  - 增加构建前清理
  - 收口本地端口与命令
- 当前结果：
  - 本地可按固定方式起站并复验
- 是否闭环：
  - 是
- 是否仍有后续增强空间：
  - 有，但当前不再阻塞交付

#### 14. 浏览器 / 本地访问链路排查

- 整改项名称：
  - 本地访问链路认知收口
- 问题表现：
  - 一度误把运行环境的 localhost 当成用户浏览器本地可访问地址

- 当前结果：

- 是否闭环：
  - 是
- 是否仍有后续增强空间：
  - 无明显阻塞问题
