# 《风控页面第一轮验收清单》

## 一、风控总览页

### 已完成项
- 已有独立入口：
  - [http://localhost:3006/risk](http://localhost:3006/risk)
- 已接后端聚合接口：
  - `/api/risk/overview`
- 已展示核心指标卡：
  - 高风险客户数
  - 高风险项目数
  - 极高风险项目数
  - 总未收金额
  - 大额未收项目数
  - 待起诉/已诉项目数
  - 未闭环项目数
- 已展示基础分布区：
  - 风险等级分布
  - 风险原因分布
  - 项目风险分布
- 已展示 Top 列表：
  - 高风险客户 Top 列表
  - 高风险项目 Top 列表
- 已接页面跳转入口：
  - Top 客户可跳风险客户页
  - Top 项目可跳风险项目页
- 已过滤明显噪声主体：
  - `合计`
  - `单位`
  - `购货单位`

### 待验证项
- 指标卡数值是否符合业务预期
- 风险原因分布是否足够反映当前风险主因
- Top 客户 / Top 项目排序是否符合“业务最该先看”的直觉
- 管理层是否能通过这一页快速定位重点风险对象

### 已知问题
- `newAlertCount` 仍是 MVP 占位，未形成稳定新增预警口径
- 分布区目前是可读性优先版，不是复杂图表版
- Top 列表字段还比较精简，未带更多上下文

### 建议优先修复项
- 优先补 `newAlertCount` 的稳定口径
- 再优化 Top 列表信息密度
- 最后再考虑图表增强，不必先做复杂视觉

## 二、风险客户列表页

### 已完成项
- 已有独立入口：
  - [http://localhost:3006/risk/customers](http://localhost:3006/risk/customers)
- 已接后端接口：
  - `/api/risk/customers`
- 已展示字段：
  - 客户名称
  - 客户类型
  - 风险等级
  - 风险原因
  - 建议动作
  - 总应收金额
  - 总未收金额
  - 项目数量
  - 高风险项目数量
  - 是否重点客户
  - 是否未闭环
- 已支持筛选：
  - 风险等级
  - 客户类型
  - 是否重点客户
  - 是否未闭环
  - 关键字搜索
- 已支持排序：
  - 总未收金额
  - 风险等级
  - 高风险项目数量
- 已支持联动：
  - 点击客户名称进入客户详情页
- 页面展示直接复用后端返回的：
  - `riskLevel`
  - `riskReasons`
  - `riskActions`
  - `triggeredRules`

### 待验证项
- 搜索是否符合使用习惯
  - 搜客户名称
  - 搜风险原因
  - 搜当前状况
- 风险原因前 2~3 条摘要是否够用
- 建议动作前 1~2 条是否足够支撑业务跟进
- “是否重点客户 / 是否未闭环”筛选是否满足日常排查

### 已知问题
- 暂未做分页交互，默认 `pageSize=100`
- 关键词搜索目前不做高亮命中
- 客户级风险仍有一部分来自项目汇总上卷，展示合理但还可更精细
- 文本摘要中仍可能出现少量 `待补数据` 占位

### 建议优先修复项
- 优先清理或弱化 `待补数据` 这类摘要占位文本
- 再补分页或更明确的结果统计
- 最后再考虑高亮命中和导出

  - 项目归属
  - 业务类型
  - 是否未闭环
  - 是否有原始档案

- 回款比例字段与项目风险直觉是否一致

### 已知问题
- 项目归属筛选当前是文本包含匹配，不是标准枚举
- `R-009 应回款月份已到未回款` 目前是第一版简化实现
- 原始档案状态和未闭环状态当前仍是 MVP 口径
- 部分项目摘要字段仍可能有占位文本

### 建议优先修复项
- 优先补强 `R-009` 的后端精度
- 再补项目归属枚举化筛选
- 最后再考虑分页、导出、批量操作

## 四、统一联动与导航

### 已完成项
- 左侧导航已补齐：
  - 风控总览
  - 风险客户
  - 风险项目
- 三个页面顶部都已有轻量模块切换：
  - 总览
  - 客户
  - 项目
- 当前页高亮已接通
- 页面间基础跳转已接通：
  - 总览 -> 风险客户
  - 总览 -> 风险项目
  - 风险客户 -> 客户详情

  - 风险项目 -> 客户详情并带项目上下文

### 待验证项
- 顶部模块切换是否足够顺手
- 左侧导航组织是否符合日常使用习惯
- 风险总览页跳客户页/项目页的节奏是否自然

### 已知问题
- 左侧导航目前是平铺，不是风控分组折叠
- 页面跳转暂不继承复杂筛选条件
- 还没有接“预警记录页 / 规则页”导航

### 建议优先修复项
- 先确认当前导航是否已经足够用
- 如果用户觉得入口太散，再做风控分组
- 不建议现在就上复杂联动状态同步

## 五、验收重点样本建议

这一轮最适合重点验收这些样本：

### 1. 云龙小学
- 客户：`成都永安建设集团有限公司`
- 项目：`云龙小学`
- 适合验收：
  - 正常项目是否不会误报高风险
  - 项目详情联动是否正常
  - 原始档案和项目上下文是否能对上

### 2. 96#地块类项目
- 客户：`四川辉航建筑工程有限公司`
- 项目：
  - `川港合作示范园96#地块`
  - `川港合作示范园先行启动区一期96#地块`
- 适合验收：
  - 风险项目页是否能正确显示
  - `R-002 / R-009 / R-011` 是否能体现
  - 点击项目名称是否能带 `projectId` 进入详情页

### 3. 青水澜湾类高金额项目
- 客户：`江西建工第三建筑有限责任公司`
- 项目：
  - `环天．青水澜湾项目`
  - `环天．青水澜湾项目37、38#`
- 适合验收：
  - 高金额高未收是否进入高风险/极高风险
  - Top 列表排序是否合理
  - 风险原因是否能看懂

### 4. 已诉 / 待起诉项目
- 重点看：
  - 业务类型为 `待起诉 / 已诉 / 诉`
  - 备注里有诉讼关键词的项目或客户
- 适合验收：
  - `R-003 / R-004 / R-010` 是否正常触发
  - 客户页和项目页是否一致显示风险原因

### 5. 高金额高未收项目
- 适合验收：
  - `R-011` 是否正确抬升风险等级
  - 总览页与项目页是否一致
  - 管理层是否能一眼看出要优先跟进的对象

### 6. 未闭环重点客户项目
- 例如：
  - `天府云城`
  - `盛世锦都`
  - `秦皇帝锦`
- 适合验收：
  - “未闭环”标签是否清楚
  - 风险客户页 / 风险项目页是否能识别这些对象

## 建议验收顺序

建议你按这个顺序看：

1. 先看风控总览页
2. 再看风险客户列表页
3. 再看风险项目列表页
4. 最后抽查 4~6 个重点样本项目，确认：
   - 风险等级
   - 风险原因
   - 建议动作
   - 客户详情联动
   - 原始档案联动
