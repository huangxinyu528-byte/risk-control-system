# Netlify 试运行可部署性检查

日期：2026-03-30  
适用范围：风控系统第一版 Netlify 试运行环境  
定位说明：本次为试运行上线，不作为正式生产上线

## 一、检查结论

### 1. 当前项目是否可直接部署到 Netlify
结论：**可以部署到 Netlify 试运行环境，但不是“零处理直接上线”，有几项必须先明确或先规避的问题。**

当前项目具备以下基础：
- 使用 `Next.js 14`，适合 Netlify 的 Next.js 运行模式
- 页面和 API 已经基本都走标准 App Router 结构
- 风控页面、客户页、总账页都依赖服务端接口聚合，适合在 Netlify Functions Runtime 中运行
- Prisma + PostgreSQL 方案本身可以部署在 Netlify，只要数据库可从 Netlify 运行环境访问

### 2. 是否有必须先处理的问题
有，主要是 3 类：

#### A. 数据库连通性必须先确认
- 当前系统真实数据依赖 `DATABASE_URL`
- 如果 Netlify Functions 无法连到 PostgreSQL，则页面只能落入开发兜底逻辑，无法作为试运行环境使用
- 所以数据库可达是试运行上线的前置条件

#### B. Prisma 生成链路需要明确
- 当前项目有 `prisma generate` 脚本，但 `package.json` 里没有 `postinstall`
- Netlify 构建时理论上可能成功，也可能因为 Prisma Client 未预生成而出问题
- 试运行前建议至少确认构建命令中已包含 Prisma Client 生成动作，或者补 `postinstall`

#### C. Excel 导入接口不适合作为 Netlify 试运行能力
- `app/api/import/excel/route.ts` 依赖：
  - `python3`
  - `child_process`
  - 临时文件写入
- 这类能力在 Netlify Functions 里不是第一版试运行的稳妥能力
- 建议本次 Netlify 试运行**不把“在线 Excel 导入”作为验收范围**
- 即使保留代码，也建议在试运行说明中明确：
  - 本次试运行主要验证“查看、查询、风控判断”
  - 不验证“在线导入”

## 二、数据库是否能从 Netlify 运行环境访问

### 1. 原则结论
结论：**能不能访问，不取决于 Netlify 本身，而取决于你的 PostgreSQL 是否允许来自 Netlify 运行环境的连接。**

换句话说：
- 如果数据库是公网可访问，且账号白名单、网络策略允许外部连接，则 Netlify 可以访问
- 如果数据库只在你电脑本地、内网、VPN 内、或只允许局域网访问，则 Netlify 无法访问

### 2. 当前项目代码对数据库的依赖情况
当前项目：
- `prisma/schema.prisma` 使用 `DATABASE_URL`
- `lib/prisma.ts` 只有在 `DATABASE_URL` 存在时才启用真实 Prisma
- 风控页、客户页、总账页等真实接口都需要数据库数据

所以试运行环境若要“看真实数据”，数据库必须满足：
- 对 Netlify Functions 可访问
- 连接串在 Netlify 环境变量中可配置

### 3. 对试运行的建议
如果你当前数据库还在本地环境，建议不要直接连本机数据库。  
更稳的试运行方式是：
- 使用一个外部可访问的 PostgreSQL（试运行库）
- 导入一份当前试运行所需数据
- 再让 Netlify 连接这套试运行库

## 三、当前项目的可部署性拆解

### 1. 页面能力
以下页面作为 Netlify 试运行目标，技术上可以进入上线范围：
- `/login`
- `/customers`
- `/customers/[id]`
- `/risk`
- `/risk/customers`
- `/risk/projects`

这些页面依赖：
- Next.js 页面渲染
- App Router API
- Prisma + PostgreSQL

### 2. API 能力
以下接口适合纳入试运行范围：
- `/api/customers`
- `/api/customers/ledger`
- `/api/risk/overview`
- `/api/risk/customers`
- `/api/risk/projects`

这些接口的特点是：
- 全部使用现有后端聚合逻辑
- 规则结果统一在后端输出
- 页面只做展示

### 3. 不建议纳入本次试运行范围的能力
第一版建议先不把下面能力作为 Netlify 试运行重点：
- `/api/import/excel`
- 本地脚本式导入、回填、批处理
- 依赖 Python / 子进程 / 本地文件系统的逻辑

## 四、必须先确认的清单

上线前必须先确认：
1. PostgreSQL 是否可从 Netlify 访问
2. `DATABASE_URL` 是否已经准备好试运行库连接串
3. `SITE_ACCESS_PASSWORD` 是否已准备好
4. Netlify 构建时 Prisma Client 是否能稳定生成
5. Excel 导入是否明确排除在试运行范围外

## 五、建议结论

### 可以作为 Netlify 试运行上线的前提
满足以下条件时，可以进入试运行上线：
- 数据库可达
- 环境变量齐备
- 构建通过
- 登录、客户、风控三条主链路验证通过

### 当前最稳妥的试运行策略
建议：
- **先把“查看 / 查询 / 风控判断”上线**
- **暂不把“在线 Excel 导入”纳入试运行**
- **启用 Netlify 密码保护**
- **使用试运行专用数据库或试运行专用连接串**

## 六、一句话结论

当前项目**可以作为 Netlify 试运行环境上线**，但必须先处理或明确以下前置条件：
- 数据库必须能从 Netlify 运行环境访问
- Prisma 构建链路必须稳定
- Excel 导入接口不建议纳入本次试运行能力范围

在以上条件满足的前提下，当前第一版页面和风控能力适合进入试运行。
